# vertx-boost-samples
Sample project to display the usage of vertx-boost (https://github.com/Areeb-Gillani/vertx-boost/) and vertx-boost-db (https://github.com/Areeb-Gillani/vertx-boost-db/). Please visit these repositories to get the basic knowledge of what I am targeting in this sample code. If you don't want to check the repos then at least make sure you have basic understanding of Vertx (https://vertx.io)

### Application Entry Point
```java
public class Application extends BoostApplication {
    @Override
    public void start() throws Exception {
        super.start();
        deployApplication("config.json");
    }

    public static void main(String[] args) {
        run(Application.class, args);
    }
}
```

### RestController
```java
@RestController
public class ExampleController extends AbstractController {
    @GetMapping("/sayHi")
    public String sayHi() {
        return "hi";
    }
    
    @GetMapping("/sayHello")
    public String sayHello(@RequestParam("username") String user) {
        return "Hello " + user;
    }
    
    @PostMapping("/sayHiToUser")
    public String sayHiToUser(JsonObject body) {
        return "Hi! " + body.getString("username");
    }
    
    @PostMapping("/replyHiToUser")
    public void replyHiToUser(JsonObject body, RoutingContext context) {
        eventBus.request("MyTopic", body, reply -> {
            if (reply.succeeded()) {
                context.json(reply.result().body());
            } else {
                context.response().setStatusCode(500).end(reply.cause().getMessage());
            }
        });
    }
}
```
#### Note
- We can't call the service function directly to keep our controller lightweight, so if you want some blocking calls, use the event bus to pass them to the worker threads.
- When using `RoutingContext` as a parameter, the return type should be `void` as you're writing the response directly to the routing context.
- `@Autowired` will not work in controller classes because all the controllers run on event loops, and one can't block the event loop's thread. Vertx will throw an exception if the event loop thread is blocked, that is why composition is prohibited.
 
### Service
```java
@Service("ExampleWorker") // Must match the name in ServiceUnits configuration
public class ExampleService extends AbstractService {
    @Autowired
    DatabaseRepo myRepo;

    @Override
    public void bindTopics() {
        eventBus.consumer("MyTopic", this::replyHiToUser);
        eventBus.consumer("someOtherTopic", this::someOtherTopic);
    }

    private void replyHiToUser(Message<Object> message) {
        JsonObject vertxJsonObject = (JsonObject) message.body();
        myRepo.saveData(vertxJsonObject)
            .onSuccess(result -> message.reply(result ? "Data Saved" : "Data saving error"))
            .onFailure(err -> message.fail(500, err.getMessage()));
    }
    
    private void someOtherTopic(Message<JsonObject> tMessage) {
        // Add your code here
    }
}
```
#### Note
- Service will never return anything directly; instead, it will use the `message.reply()` method to return the response.
- **Override `bindTopics()` method** (not `start()`) to bind all event bus consumers.
- All repository operations return `Future<T>` - always handle with `.onSuccess()` and `.onFailure()` for proper async handling.
- Use `message.fail(statusCode, errorMessage)` to propagate errors back to the caller.
- `TestParametersMapper.INSTANCE` will be automatically generated by vertx-codegen. Please refer to the Configuration section.

### Model
I took the liberty of using vertx-code-gen library to generate models on the fly. You can either use the annotation based model generation or create something similar to Mapper class /mappers/Mapper.java
```java
@DataObject
@ParametersMapped
public class Test {
    @Column(name = "message")
    String message;
    
    @Column(name = "unique_id")
    String id;
    
    @Column(name = "entry_by")
    String entryBy;
    
    @Column(name = "entry_time")
    String entryTime;
    
    // Required: Constructor with JsonObject for vertx-codegen
    public Test(JsonObject json) {
        this.id = json.getString("unique_id");
        this.message = json.getString("message");
        this.entryBy = json.getString("entry_by");
        this.entryTime = json.getString("entry_time");
    }
    
    public Test() {}
    
    // Getters and setters...
}
```
#### Note:
- In case of code-gen, a model **must have a constructor with JsonObject as param**.
- Also needs a `package-info.java` for package identification.

### Repository
```java
@Repository("Primary") // Must match the connection name in dbConnections config
public class DatabaseRepo extends CrudRepository<Test> {
    public DatabaseRepo(String connectionName, JsonObject config) {
        super(connectionName, config);
    }
    
    public Future<Boolean> saveData(JsonObject vertxJsonObject) {
        Test t = new Test();
        t.setEntryBy("Test");
        t.setEntryTime(System.currentTimeMillis() + "");
        t.setId(Math.random() + "");
        t.setMessage("Message saved for " + vertxJsonObject.getString("username"));
        return save(t, "Insert into Test values (#{id}, #{message}, #{entry_by}, #{entry_time})", TestParametersMapper.INSTANCE);
    }
}
```
#### Note:
- The `@Repository("Primary")` value must match the connection name defined in `dbConnections` in your config.json.
- All CRUD operations return `Future<T>` for async handling.

### Configuration

#### config.json
```json
{
  "server": {
    "http": {
      "port": 8087,
      "enable": true,
      "instance": 1
    }
  },
  "ServiceUnits": {
    "ExampleWorker": {
      "instance": 5,
      "poolSize": 6,
      "type": "W"
    }
  },
  "dbConnections": {
    "Primary": {
      "dbName": "test_db",
      "dbHost": "localhost",
      "dbPort": 3306,
      "dbUsername": "root",
      "dbPassword": "root",
      "dbConnectionPoolSize": 10,
      "dbType": "MYSQL",
      "dbRetryCount": 5,
      "dbRetryInterval": 1000
    }
  }
}
```
#### Config Options:
- **ServiceUnits**: Configure worker services
  - `instance`: Number of verticle instances
  - `poolSize`: Worker pool size
  - `type`: Threading model - `W` (Worker), `EL` (Event Loop), `VT` (Virtual Thread)
- **dbConnections**: Named database connections
  - `dbType`: Supported values: `MYSQL`, `POSTGRESQL`, `MSSQL`, `ORACLE`

#### Step 1: Enable Annotation Processing
To process annotations one should enable annotation processing in the respective IDE. e.g. In IntelliJ: File > Settings > "Search Annotation" > Enable Annotation Processing

#### Step 2: Gradle Dependencies
Gradle has been evolving so much and most of the examples on internet are for older versions of gradle. To process relative annotations you need to have these lines in dependencies in build.gradle.kts:
```kotlin
dependencies {
    // Core Vertx libraries
    implementation("io.vertx:vertx-web:4.5.8")
    implementation("io.vertx:vertx-config:4.5.8")
    implementation("io.vertx:vertx-core:4.5.8")
    
    // Boost libraries
    implementation("io.github.areebgillani:vertx-boost:1.1.0")
    implementation("io.github.areebgillani:vertx-boost-db:1.1.0")
    
    // Database client (choose based on your DB)
    implementation("io.vertx:vertx-mysql-client:4.5.8")
    // implementation("io.vertx:vertx-pg-client:4.5.8")      // For PostgreSQL
    // implementation("io.vertx:vertx-mssql-client:4.5.8")   // For MSSQL
    // implementation("io.vertx:vertx-oracle-client:4.5.8")  // For Oracle
    
    implementation("io.vertx:vertx-sql-client-templates:4.5.8")
    
    // To generate mapper from @DataObject annotation
    compileOnly("io.vertx:vertx-codegen:4.5.8")
    annotationProcessor("io.vertx:vertx-codegen:4.5.8:processor")
    annotationProcessor("io.vertx:vertx-sql-client-templates:4.5.8")
}

repositories {
    mavenLocal()
    mavenCentral()
    maven("https://jitpack.io")
}
```

### Available Annotations

| Annotation | Target | Description |
|------------|--------|-------------|
| `@RestController` | Class | Marks a class as an HTTP controller (must extend `AbstractController`) |
| `@Service("name")` | Class | Marks a class as a worker service (must extend `AbstractService`) |
| `@Repository("connection")` | Class | Marks a class as a repository with named DB connection |
| `@Autowired` | Field | Injects dependencies (works in services only, not controllers) |
| `@GetMapping("/path")` | Method | Maps HTTP GET requests |
| `@PostMapping("/path")` | Method | Maps HTTP POST requests |
| `@PutMapping("/path")` | Method | Maps HTTP PUT requests |
| `@DeleteMapping("/path")` | Method | Maps HTTP DELETE requests |
| `@PatchMapping("/path")` | Method | Maps HTTP PATCH requests |
| `@PathVariable("name")` | Parameter | Extracts path variable from URL |
| `@RequestParam("name")` | Parameter | Extracts query parameter from URL |
